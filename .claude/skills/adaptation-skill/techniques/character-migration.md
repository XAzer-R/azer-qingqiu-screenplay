# 子技能4：人物迁移

## 功能

设计原著人物到剧本人物的转化方案——决定保留谁、合并谁、新增谁、削减谁。

**前置输入：** 原著解析报告 + 戏剧点提炼报告 + 结构映射方案

---

## 迁移原则

### 1. 功能优先

每个剧本角色必须有明确的叙事功能：
- 推动主线
- 制造冲突
- 揭示主角的另一面
- 承载支线

**没有功能的角色，不进入剧本。**

### 2. 角色数量控制

| 剧本类型 | 建议主角 | 建议配角 | 理由 |
|---------|---------|---------|------|
| 短片 | 1-2 | 2-3 | 时间有限，角色精简 |
| 短剧（6-12 集） | 1-2 | 4-6 | 保持聚焦 |
| 系列剧（12+ 集） | 2-3 | 6-10 | 支撑多线叙事 |

### 3. 合并原则

以下情况考虑合并角色：
- 两个角色的叙事功能重叠
- 一个角色只出现 1-2 次且功能可被其他角色替代
- 合并后能制造更强的戏剧冲突（如"帮手"和"对手"合并为一个有双重身份的角色）

---

## 迁移流程

### 步骤 1：角色清单

列出原著中所有角色及其功能：

```
原著角色清单
════════════

主要角色：
1. {名} — 功能：{在故事中的作用} — 出场频率：高
2. {名} — 功能：{作用} — 出场频率：高

次要角色：
1. {名} — 功能：{作用} — 出场频率：中
2. ...

边缘角色：
1. {名} — 功能：{作用} — 出场频率：低
2. ...
```

### 步骤 2：迁移决策

```
人物迁移决策
════════════

✅ 保留（直接迁移）：
1. {名} — 理由：{为什么保留}

🔄 合并：
1. {名A} + {名B} → {新角色名} — 理由：{为什么合并}
   合并方式：{保留谁的外在特征 + 谁的叙事功能}

➕ 新增：
1. {新角色名} — 功能：{为什么需要新增}
   在原著中的对应：{无 / 从某个角色分拆}

❌ 削减：
1. {名} — 理由：{为什么削减}
   功能转移：{其功能由谁承担}
```

### 步骤 3：内心外化方案

原著中通过内心活动展现的角色特质，如何用影视手段表达：

```
内心外化方案
════════════

{角色名}：

原著方式：{内心独白/心理描写示例}
影视替代：
- 方案A（动作）：{用什么动作替代}
- 方案B（对白）：{用什么潜台词替代}
- 方案C（他人反应）：{通过其他角色的反应表现}
推荐方案：{A/B/C}
```

### 步骤 4：角色关系重构

原著的角色关系网络可能不适合影视，需要重构：

```
关系重构
════════

原著关系：{A 和 B 是同事}
剧本关系：{A 和 B 是师徒}
重构理由：{师徒关系比同事关系有更强的情感张力和权力落差}
对故事的影响：{具体影响}
```

---

## 输出格式

```
人物迁移方案
════════════

原著角色总数：{N}
剧本角色总数：{N}（主角 {N} + 配角 {N}）

保留：{N} 个
合并：{N} 组 → {N} 个新角色
新增：{N} 个
削减：{N} 个

需外化处理的角色：{N} 个
关系重构：{N} 处

人物关系图（Mermaid）：
（在改编分析报告中呈现）
```
