# 小说消化

## 用途

将一本小说的原文转化为系统可用的参考素材。输出不是读后感，是**按方法论标准拆解的技术分析**——编剧 agent 和审查员 agent 可以直接引用。

---

## 前置条件

1. 小说文本已放入 `references/novels/{书名}/` 目录
2. 文件格式：`.md` 或 `.txt`，可以是完整文本或按章节分文件
3. 如果是外语作品，放中文译本（系统全中文工作）

---

## 输入目录结构

```
references/novels/{书名}/
├── raw/                    # 原文（用户放置）
│   ├── 全本.md             # 或按章节分：
│   ├── ch01.md
│   ├── ch02.md
│   └── ...
└── （以下由 skill 生成）
    ├── INDEX.md             # 结构拆解
    ├── dialogue.md          # 对白范例
    ├── scenes.md            # 场景范例
    ├── narrative.md         # 叙事技法
    └── project-mapping.md      # 与当前项目的对标映射
```

---

## 消化流程（三层）

### 第一层：骨架扫描

**目标：** 快速掌握全书结构，标记值得精读的段落。

**操作：** 按章节/段落逐块读取，每块提取：

```
章节/段落号 | 一句话概括 | 结构功能 | 值得精读？ | 原因
```

结构功能从以下选择：
- 开场锚定 / 日常世界建置
- 激励事件 / 第一转折
- 上升动作 / 冲突升级
- 中点反转
- 危机 / 至暗时刻
- 高潮
- 新常态 / 尾声
- 支线（B/C Plot）
- 呼吸段落

**标记"值得精读"的标准：**
- 对白密度高且质量好的段落
- 沉默/无对白承载重情感的段落
- 结构上的关键转折（激励事件、中点、高潮）
- 与当前项目某个场景有直接对标价值的段落
- 叙事手法特别的段落（时间跳切、视角切换、物件叙事等）

**输出：** 内部骨架表（不写入文件，用于指导第二层）

### 第二层：定向精读

**目标：** 精读标记的段落，按四个维度提取素材。

回到第一层标记的段落，逐个精读，提取以下四类素材：

**A. 结构素材（→ INDEX.md）**
- 这个段落对应 Truby 22 步的哪一步？
- McKee 价值转变：进入什么价值状态 → 离开什么状态？层级？
- 鸿沟：角色行动的期望结果 vs 实际结果？
- 这个转折是怎么准备的（伏笔/铺垫在哪里）？

**B. 对白素材（→ dialogue.md）**
- 引用原文对白（完整段落，保留上下文）
- Mamet 分析：每句台词的"动作"是什么？策略升级在哪里？
- Kasdan 分析：表层含义 vs 深层含义？潜台词是什么？
- 角色语言指纹：这段对白遮住名字能猜出谁说的吗？怎么猜？
- 沉默分析：如果段落中有关键沉默，沉默承载了什么？

**C. 场景素材（→ scenes.md）**
- 判定场景类型（对照 `references/scenes/` 的 7 个类型：confrontation / silence_breakdown / silent / death / reunion / ghost_flashback / ensemble_unseen / 其他）
- 按该类型的 `_README.md` 格式提取
- 如果是新类型（现有 7 个不覆盖），单独标注

**D. 叙事技法素材（→ narrative.md）**
- 物件叙事：哪些物件承载了情感或主题？怎么做到的？
- 节奏控制：这个段落的快慢节奏怎么设计的？
- 视角选择：为什么用这个视角？换一个会怎样？
- 信息控制：作者在这个段落隐藏了什么信息？什么时候揭示的？
- 时间处理：有没有时间跳切、闪回、压缩/膨胀？

### 第三层：合成输出

将第二层的素材合成为五个标准化输出文件。

### dialogue.md — 对白范例

```markdown
# {书名} · 对白范例

共提取 {N} 段对白。按质量排序，最好的在前面。

---

## 范例 1：{场景简述}

**位置：** 第{X}章 / {上下文一句话}
**对白类型：** {对峙 / 试探 / 告别 / 沉默交锋 / 信息博弈 / ...}

**原文：**
> （完整引用，保留上下文动作描写）

**分析：**
- **Mamet 动作链：** 每句的"动作"是什么 → 策略怎么升级
- **Kasdan 潜台词：** 表层在说什么 → 深层在说什么
- **语言指纹：** 遮住名字怎么猜出谁说的
- **沉默：** 如果有沉默，承载了什么

**本剧启示：** 这段技法可以用在当前项目的哪里、怎么用
```

## 特殊处理

### 非小说类作品（如《千面英雄》）

理论类作品跳过对白和场景提取，改为：
- INDEX.md → 核心理论框架 + 引用的神话/故事原文
- narrative.md → 理论中的叙事原则
- project-mapping.md → 理论框架与本剧的映射

### 超长作品

如果小说超过 15 万字：
- 第一层骨架扫描覆盖全本
- 第二层精读控制在 10-15 个段落以内
- 优先精读对当前项目当前创作阶段最有用的段落

### 多卷作品（如《基地》系列、《三体》三部曲）

每卷单独消化，各自生成五个文件。最后做一个跨卷汇总的 `cross-volume.md`。

---

## 消化完成后

1. 更新 `.drama-state.json` 的 `novel_indexes` 字段
2. 通知主控："{书名} 消化完成，生成 5 个参考文件"
3. 如果发现了现有 7 个场景类型不覆盖的新类型，建议在 `references/scenes/` 下新建目录

## 命令

`/消化 {书名}` — 启动对指定书目的消化流程

执行者：screenwriter agent（它最懂方法论体系）
